# SAK-52889: consolidate tagging

Run the Sakai 27 conversion for your database after applying the Sakai 26 conversions, with Sakai stopped and a database backup available. The shared Tag Service tables must already exist.

The conversion widens shared collection IDs to accommodate Sakai's 99-character site IDs, copies Conversations tags into their site's shared collection, and copies topic associations into `tagservice_tagassociation`. Existing shared tags are retained, even when labels match. Conversations IDs become deterministic 36-character string IDs; labels, descriptions, unused tags, and links are preserved.

This is a one-time conversion against the standard Sakai 26 schema. It assumes the source tables and original foreign-key names exist. MySQL uses `tagservice_tag_ibfk_1` and preserves its `ON DELETE RESTRICT ON UPDATE RESTRICT` rules. Empty tag tables need no special handling. Run the MySQL client without `--force`; the Oracle script stops on SQL errors. If the upgrade fails, restore the backup before repeating it.

The conversion drops `CONV_TOPIC_TAGS`, `CONV_TAGS`, the old tag ID generator, and `TAGGABLE_LINK`. Legacy Taggable data is deliberately retired; it is not converted into shared labels.

Deploy the corresponding SAK-52889 Sakai code before restarting. Use a clean deployment, or remove the obsolete `sakai-taggable-impl` component and `sakai-taggable-api-*.jar` / `sakai-taggable-hbm-*.jar` from the old deployment. Merely deploying updated modules over the old installation does not remove those artifacts.

Conversations uses the site's shared vocabulary. Editing or deleting a tag through Conversations affects the same tag used by other tools; Conversations retains its existing tag-management permission checks. Review any custom role grants with that shared scope in mind.

Oracle conversion requires validation in an Oracle environment.
